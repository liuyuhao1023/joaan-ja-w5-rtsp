# 网络与静态地址

本文全部为示例地址：摄像头 `192.168.10.250`，服务器 `192.168.10.10`，光猫 `192.168.10.1`，下级路由器 WAN `192.168.10.2` / LAN `192.168.20.1`，NVR `192.168.20.20`。

## UI 没有入口，如何设置静态 IP？

本次通过摄像头 ONVIF Device 服务的 `GetNetworkInterfaces` 确认接口 token、设备 MAC 和网络配置，再发送 `SetNetworkInterfaces`。请求包含接口 token、IPv4 Enabled、Manual Address/PrefixLength 和 DHCP=false。**没有通过光猫设置静态 DHCP 绑定。**

此操作会改变连接地址，因此仓库不提供默认执行的改网脚本。请先备份原配置，确认设备身份、网关、地址冲突和恢复方式。写入响应与实际生效时间可能不同，必要时只重启目标摄像头，随后从新地址读回确认。不要仅凭请求返回 success 判断。

## 第二台如何避免冲突？

先规划一段摄像头专用地址，例如 `.240–.250`，确认无人使用，再将 DHCP 动态池限制在 `.2–.239`。为每台设备分配不同地址并记录设备身份。不要直接复制第一台的静态 IP 到第二台。修改 DHCP 池前核对现有客户端，避免错误影响其他设备。

Web 的“添加摄像头”登记取流配置，不会改摄像头 IP、不会改光猫 DHCP 池，也不保证探测到所有 IP 冲突。

## 连接检查顺序

1. 服务器能连接摄像头 554。
2. MediaMTX 原始流有实际数据，FFmpeg 能解码帧。
3. `joaan/nvr` 存在 H.264 实际输出。
4. NVR 能访问服务器 8554 和 8899。
5. NVR 可取得画面，再检查录像回放和重启恢复。

跨网段不依赖 WS-Discovery 自动发现。最小代理按 IP 手动添加。若 RTSP 采用 TCP，媒体走同一 TCP 会话，较容易避免多级 NAT 下额外 UDP 端口问题；它不能解决基础路由不可达。
